# Runbook: Redfin is blocking us (403, empty pages, login wall)

## Symptoms

- `extract.discover_sold` stops with "N pages in a row had no listings" and exits with code 2. It saves a screenshot to
  `redfin/output/debug_blocked.png`.
- `extract.fetch_sold` / `extract.fetch_active` stop with "8 failures in a row".
- `extract.census` prints "no result header" and writes a manifest with `complete: false`.
- In the Action, the Discover step fails (red X). Extract is then skipped; Transform still runs (`if: always()`), so pages
  already in bronze still reach silver.

The usual cause is an expired `aws-waf-token` cookie.

## Fix: export fresh cookies

1. In Chrome, install a cookie exporter (e.g. "Cookie-Editor").
2. Open https://www.redfin.ca, log in if you have an account, and browse a few listings normally for a couple of minutes.
3. Export all redfin.ca cookies as JSON.
4. **Local runs**: save the file as `redfin/chrome_cookies.json` (gitignored; never commit it). Override the location
   with `REDFIN_COOKIE_FILE` if needed.
5. **The daily Action**: paste the same JSON into the repo secret `REDFIN_COOKIES_JSON`
   (Settings → Secrets and variables → Actions). The workflow writes it to `redfin/chrome_cookies.json` on each run.
6. Test small before the next scheduled run (from the repo root):
   ```bash
   python -m redfin.extract.fetch_sold --limit 5
   MAX_NEW_URLS=20 python -m redfin.extract.discover_sold
   ```

Fresh cookies usually last a few weeks to a few months.

## If fresh cookies don't help

- Wait 24 hours before retrying, so the IP cools down. Don't retry in a loop.
- Lower the volume for a few days: set `MAX_SCRAPE_COUNT` lower in `daily_scrape.yml` (it is 300 per run; the caps live in
  `redfin/src/redfin/config.py`).
- Try another network (e.g. a mobile hotspot) for a local run.

Pages already in bronze are never lost: once extract works again, `transform.sold --incremental` catches silver up.
